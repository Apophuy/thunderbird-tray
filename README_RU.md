# thunderbird-tray

[English version](README.md)

`thunderbird-tray` — небольшое дополнение к Mozilla Thunderbird 156 и новее,
которое работает в системном трее Linux. Расширение Thunderbird на Manifest V3
передаёт состояние непрочитанных писем локальному процессу на Rust через Native
Messaging. Интерфейс трея не требует Qt или GTK; первой полностью поддерживаемой
средой станет KDE Plasma Wayland. Для параметров предусмотрено полноценное
нативное окно настроек.

Это новая реализация, вдохновлённая пользовательским поведением Birdtray. Проект
не является форком Birdtray и не использует его исходный код или архитектуру.

Проект находится в активной разработке. Текущая реализация соединяет расширение
Thunderbird 156+ с локальным Rust-процессом и показывает суммарное состояние
непрочитанных писем из папок «Входящие» через StatusNotifierItem и нативное меню
DBusMenu. Полноценное окно настроек управляет запуском, оформлением, треем и
интеграцией с Thunderbird.

## Требования

- Rust 1.85 или новее, включая `rustfmt` и `clippy`;
- Node.js 22.13 или новее и npm;
- Thunderbird 156 или новее для интеграционной проверки.

## Сборка и тестирование

```sh
cargo build --workspace
cargo test --workspace
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings

npm --prefix extension ci
npm --prefix extension run lint
npm --prefix extension test
npm --prefix extension run build
```

Подробности приведены в [руководстве разработчика](docs/development.md), а

KDE Plasma — в [руководстве по Wayland](docs/wayland.md). Для локальной
настройки права root не требуются.

## Установка

Основной релизный артефакт — пакет Debian. Он устанавливает приложение в
`/opt/thunderbird-tray`, предоставляет команду `thunderbird-tray` через
`/usr/bin` и регистрирует Native Messaging host для всей системы. XPI из пакета
нужно установить через менеджер дополнений Thunderbird; пакет никогда не
изменяет профиль Thunderbird напрямую. Также доступен переносимый архив для
установки без root. Команды установки, обновления и удаления приведены в
[руководстве по релизу и установке](docs/release.md).

```sh
./scripts/build-release.sh
./scripts/check-release.sh
sudo apt install ./dist/release/thunderbird-tray_0.1.8_amd64.deb
```

После этого установите
`/opt/thunderbird-tray/share/thunderbird-tray/thunderbird-tray.xpi` через
**Дополнения и темы → Расширения → Установить дополнение из файла…** в
Thunderbird.

## Конфигурация

По умолчанию используется файл
`$XDG_CONFIG_HOME/thunderbird-tray/config.toml`, а если переменная не задана —
`~/.config/thunderbird-tray/config.toml`. Поддерживаются английский и русский
языки. Значение `language = "auto"` выбирает русский для русской системной
локали, а в остальных случаях — английский. Полный список начальных параметров
есть в [`packaging/config.example.toml`](packaging/config.example.toml).

Откройте **thunderbird-tray** из меню приложений, выберите **Настройки…** в
трее или выполните `thunderbird-tray settings`. В обычном изменяемом по размеру
окне доступны системная, светлая и тёмная темы. Там же можно включить
пользовательскую автозагрузку, запуск Thunderbird вместе со службой и запуск
Thunderbird скрытым в трее. По умолчанию эти параметры выключены.
При открытии приложения настроек сервис трея запускается для текущего сеанса;
это не включает автозапуск для следующих входов в систему.
Кнопка **Применить** активна только при наличии изменений: она сохраняет
настройки, при необходимости запускает сервис и оставляет окно открытым.
**Готово** применяет имеющиеся изменения и закрывает окно либо просто закрывает
его, если изменений нет; **Отмена** закрывает без сохранения текущих правок.
Автозапуск отдельно управляет следующими входами в систему.

Команда `thunderbird-tray doctor` выводит локализованную безопасную сводку
активной конфигурации и интеграции с рабочим столом. Она проверяет сеансовую
шину, службу трея, соединение с расширением, выбранный бэкенд, нативный
манифест и исполняемый файл Thunderbird, не выводя данные почты. Список
параметров доступен через `thunderbird-tray --help`.

Обычная сборка не зависит от X11. Для настоящего рабочего стола X11 можно
включить необязательный EWMH-бэкенд командой
`cargo build -p thunderbird-tray --features x11`. См.
[матрицу резервных сред](docs/fallbacks.md).

## Интерфейс трея

Общая иконка приложения и расширения — оригинальная прозрачная псевдообъёмная
янтарная птица с конвертом. При непрочитанных письмах внешний и внутренний
контуры конверта становятся красными, а индикатор показывает `1`–`99` или `99+`;
в тексте сохраняется точное количество. Нативное меню показывает текущее состояние
«Входящих», позволяет запросить полный свежий снимок и содержит сохраняемый
переключатель языка: «Автоматически», English и Русский. В поддерживаемом сеансе
KDE Plasma Wayland пункт открытия восстанавливает и активирует самое верхнее
окно Thunderbird; если окна нет, запускается настроенный исполняемый файл.
Управление существующим окном учитывает возможности выбранного бэкенда, а при
отсутствии такой возможности используется запуск процесса.
Двойное нажатие на значок трея открывает или активирует Thunderbird; нативное
меню доступно по контекстному нажатию правой кнопкой.

В поддерживаемом KDE Plasma Wayland действие **Скрыть Thunderbird** сворачивает
окно и убирает его из панели задач, не прекращая проверку почты. Публичные API
Thunderbird и KWin не позволяют перехватить кнопку закрытия до закрытия окна, поэтому
вместо ложной эмуляции используется явное действие скрытия.
Обычная кнопка сворачивания также убирает окно из панели задач, пока работает
`thunderbird-tray`; открыть окно снова можно из меню или двойным нажатием по
значку в трее.

Иконки встроены в нескольких размерах, поэтому основная часть интерфейса трея
не зависит от установленной темы значков. Оформление меню, навигацию с
клавиатуры и интеграцию с темой обеспечивает сама Plasma.

Треем владеет один постоянный процесс с известным именем в пользовательской
шине D-Bus. После закрытия Thunderbird значок переходит в состояние «нет
соединения», но процесс трея продолжает работать; при следующем запуске
Thunderbird выполняется новое рукопожатие и показывается свежий снимок
«Входящих». Повторный запуск не создаёт второй значок, а после перезапуска
оболочки Plasma регистрация значка восстанавливается.
Сам процесс трея не подключается к почтовым серверам, поэтому при закрытом
Thunderbird проверка почты не выполняется.

## Диагностика

Команда `thunderbird-tray doctor` показывает текущее состояние интеграции, а
`thunderbird-tray --log-level debug` включает подробную диагностику в stderr.
Если расширение не подключается, проверьте указанные `doctor` нативный манифест
и исполняемый файл. Если значок отсутствует, убедитесь, что рабочий стол
предоставляет StatusNotifierItem host. Подробные проверки и известные
ограничения приведены в [руководстве по релизу](docs/release.md) и
[руководстве по Wayland](docs/wayland.md).

## Конфиденциальность

Источником истины об учётных записях, папках и непрочитанных письмах остаётся
Thunderbird. Расширение передаёт локальному процессу через Native Messaging
только идентификаторы и отображаемые имена учётных записей, а также суммарное
число непрочитанных писем во «Входящих». Темы и содержимое писем, адреса
отправителей и учётные данные не передаются. Сетевых соединений для этого нет.

## Текущие ограничения

- В общем счётчике учитываются только папки «Входящие».
- Нативные обнаружение, активация, скрытие и показ окна поддерживаются в
  проверенных во время запуска сеансах Plasma/KWin 6 Wayland (протестировано с
  KWin 6.3.6). D-Bus-интерфейс загрузки скриптов KWin чувствителен к изменениям;
  при ошибке приложение безопасно переходит к запуску процесса.
- Управление окнами X11 включается необязательной сборочной возможностью `x11`
  и требует EWMH-совместимого оконного менеджера; живая проверка на отдельном
  рабочем столе X11 пока не выполнена.
- В GNOME, Sway, Hyprland и других Wayland-композиторах работают трей, счётчик
  и запуск процесса без ложного обещания глобального управления окнами. Для
  отображения трея рабочий стол должен предоставлять StatusNotifierItem host.
- Поддерживается только Linux; первой целевой средой является KDE Plasma
  Wayland.
